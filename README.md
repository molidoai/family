# هم‌سهم اندروید — نسخه ۲.۱.۰
نام بسته: ir.molido.hamsahm — حداقل Android 7.0 (API 24). به Android System WebView یا Chrome به‌روز نیاز دارد.

این پروژه نسخه مستقل و آفلاین هم‌سهم را با فایل‌های داخل APK اجرا می‌کند؛ به هاست، دامنه یا GitHub Pages نیاز ندارد. شامل اعضا، تعهد سهم ماهانه، وام و اقساط شمسی، دفتر گردش حساب، ابطال با سابقه، قرعه‌کشی، لینک پرداخت، صورت‌حساب و پشتیبان است. اطلاعات بین مرورگر سایت و این اپ مستقل است؛ برای انتقال، از سایت پشتیبان JSON بگیرید و در اپ بازیابی کنید.

## دانلود نسخه امضاشده
[دانلود Hamsahm.apk](https://github.com/molidoai/family/releases/latest/download/Hamsahm.apk)

## نصب
APK ارائه‌شده را روی گوشی دانلود و باز کنید؛ در صورت درخواست، اجازه نصب از همین منبع را در تنظیمات اندروید بدهید. این نسخه خارج از فروشگاه منتشر شده است و نصب/اجرای روی دستگاه واقعی در محیط ساخت بررسی نشده است. ابتدا با «نمایش صندوق نمونه» گردش کار را امتحان کنید. کامپایل جاوا، تولید DEX، بسته‌بندی و امضای APK در محیط ساخت انجام شده و امضای فایل و هم‌ترازی آن بررسی شده‌اند.

## کار با فایل‌ها
- دانلود پشتیبان و CSV، پنجره استاندارد «ذخیره فایل» اندروید را باز می‌کند. بعد از انتخاب مقصد، تکمیل عملیات با پیام «فایل ذخیره شد» مشخص می‌شود؛ پیام اولیه داخل صفحه صرفاً راهنمای پشتیبان است.
- بازیابی پشتیبان از انتخابگر فایل گوشی انجام می‌شود؛ فایل JSON با سقف ۱۰ مگابایت را انتخاب کنید.
- پیش از بازیابی، ابتدا **پشتیبان فعلی را جداگانه ذخیره کنید**. در زمان بازیابی، برنامه منتظر تکمیل ذخیره پشتیبان قبلی می‌ماند. اگر پنجره ذخیره را لغو کنید یا نوشتن فایل ناموفق باشد، جایگزینی اطلاعات متوقف می‌شود.
- چاپ و ذخیره PDF از سرویس چاپ اندروید استفاده می‌کند؛ وجود گزینه «Save as PDF» یا سرویس چاپ به دستگاه وابسته است.

## پرداخت
لینک HTTPS صفحه پرداخت آماده را در تنظیمات وارد کنید. لینک در مرورگر خارجی باز می‌شود؛ اطلاعات کارت داخل اپ دریافت نمی‌شود. مدیر باید وصول وجه را بررسی و واریز را ثبت کند؛ تأیید خودکار درگاه، ثبت‌نام آنلاین اعضا و همگام‌سازی بین گوشی‌ها در این نسخه وجود ندارد. بازکردن درگاه به اینترنت در مرورگر نیاز دارد؛ بقیه کارها آفلاین هستند.

## نگهداری داده
ذخیره مالی در فضای خصوصی WebView اپ است و رمزگذاری برنامه‌ای ندارد. ورود با رمز یا اثر انگشت در این نسخه پیاده‌سازی نشده است؛ از قفل دستگاه استفاده کنید. حذف اپ یا پاک‌کردن داده آن، اطلاعات محلی را حذف می‌کند؛ پشتیبان JSON را خارج از اپ نگه دارید. Android Auto Backup خاموش است. هیچ مجوز دوربین، مخاطبین یا دسترسی فراگیر به حافظه درخواست نشده است. سایت‌ها و iframeهای خارجی داخل WebView بارگذاری نمی‌شوند؛ پل بومی فقط روی محتوای بسته‌بندی‌شده فعال است.

## ساخت مجدد در GitHub
این پوشه یک پروژه اندروید مستقل است؛ فایل‌هایش باید در ریشه مخزن جداگانه قرار بگیرند، یا مسیر workflow و دستورات آن متناسب با پوشه اصلاح شود. فایل `.github/workflows/android.yml` با هر push روی main و اجرای دستی، `app-debug.apk` را به عنوان Artifact تولید می‌کند.

با JDK 17، Android SDK 35 و Gradle 8.9: `gradle :app:assembleDebug`.

APK تحویلی با کلید اختصاصی هم‌سهم امضا شده است. خروجی debug گیت‌هاب امضای دیگری دارد و **روی APK تحویلی به‌عنوان آپدیت نصب نمی‌شود**. برای آپدیت بدون حذف داده باید همان شناسه بسته و کلید امضای اصلی حفظ شود. کلید و رمز آن در پروژه عمومی وجود ندارند و جداگانه به صورت خصوصی نگهداری می‌شوند؛ هرگز فایل کلید امضا یا رمز را به مخزن عمومی آپلود نکنید.

این نسخه برای بررسی آپدیت از مجوز اینترنت و برای نمایش نصب‌کننده اندروید از REQUEST_INSTALL_PACKAGES استفاده می‌کند. صفحات وب خارجی همچنان داخل WebView مسدودند.

منطق مالی وب در `app/src/main/assets/www/core.js` است؛ این نسخه همان منطق دارای ۱۸ آزمون مالی و تقویم در هم‌سهم وب ۲.۰ را استفاده می‌کند.


## به‌روزرسانی امضاشده در نسخه ۲.۱.۰
- همان کلید خصوصی نسخه‌های ۲.۰.۱ و ۲.۰.۲ حفظ شده است؛ نسخه جدید روی نسخه قبلی قابل نصب است.
- بررسی خودکار هنگام بازکردن یا بازگشت به برنامه، با فاصله حداقل ۲۴ ساعت از آخرین پاسخ موفق؛ وقتی برنامه بسته است کار زمان‌بندی‌شده پس‌زمینه وجود ندارد.
- تنظیمات ← به‌روزرسانی هم‌سهم: بررسی دستی و خاموش/روشن‌کردن بررسی خودکار.
- تنها آخرین انتشار پایدار از `https://api.github.com/repos/molidoai/family/releases/latest` خوانده می‌شود. درخواست بدون توکن است؛ مخزن و Release باید عمومی و از اینترنت گوشی قابل دسترس باشند.
- فایل باید با نام دقیق **Hamsahm.apk** به Release اضافه شود؛ tag باید مثل `v2.1.1` و برابر versionName داخل APK باشد. versionCode نیز باید افزایش یابد.
- متادیتای فایل باید digest SHA-256 گیت‌هاب را داشته باشد. پیش از نصب، اندازه و هش، نام بسته، نسخه، حداقل اندروید و برابری امضای APK با برنامه نصب‌شده بررسی می‌شود. نشانی اولیه فقط از همین مخزن پذیرفته می‌شود و redirectها به میزبان‌های مشخص GitHub محدودند.
- دریافت با انتخاب کاربر در پیام نسخه جدید آغاز می‌شود. نصب با تأیید اندروید است و نصب مخفی یا بی‌اجازه انجام نمی‌شود. در اندروید ۸ به بالا ممکن است لازم باشد «نصب از هم‌سهم» را در تنظیمات مجاز کنید.
- فایل نصب در cache خصوصی نگهداری و فقط با مجوز خواندن موقت به نصب‌کننده اندروید داده می‌شود. دریافت APK به معنی نصب موفق نیست.
- در محیط ساخت فقط کامپایل، آزمون سیاست نسخه/نشانی/هش، اعتبار امضا و بسته‌بندی بررسی شده‌اند. چرخه دانلود، صفحه اجازه نصب و نصب روی گوشی واقعی هنوز آزموده نشده‌اند.

## فعال‌کردن انتشار خودکار از GitHub Actions
این پوشه را به عنوان ریشه پروژه اندروید در مخزن `molidoai/family` قرار دهید. اگر سایت قبلی هم در همان مخزن می‌ماند، قبل از آپلود مسیرها و workflow باید متناسب با ساختار مخزن تنظیم شوند؛ محتوا را کورکورانه جایگزین نکنید.

کلید امضای اصلی و رمز در بایگانی خصوصی جداگانه نگهداری می‌شوند؛ آن را به مخزن عمومی آپلود نکنید. در GitHub Settings → Secrets and variables → Actions این Secretها را تعریف کنید:
- `HAMS_KEYSTORE_BASE64`: Base64 فایل hamsahm.jks اصلی.
- `HAMS_KEYSTORE_PASSWORD`: رمز اصلی keystore.
- `HAMS_KEY_PASSWORD`: همان رمز کلید؛ اگر خالی باشد از رمز keystore استفاده می‌شود.

workflow روی main خروجی debug می‌سازد که مناسب آزمون است و برای آپدیت نسخه اصلی قابل استفاده نیست. روی tag با پیشوند `v`، نسخه release با کلید اصلی امضا و به Releases با نام `Hamsahm.apk` منتشر می‌شود. بدون Secretهای کلید، انتشار release متوقف می‌شود و به امضای debug برنمی‌گردد.

پیش از هر انتشار، versionName و versionCode را در app/build.gradle افزایش دهید و tag را دقیقاً برابر versionName با پیشوند v بگذارید. برای انتشار APK امضاشده فعلی، workflow به نام Publish signed Hamsahm 2.1.0 از فایل releases/Hamsahm.apk استفاده می‌کند؛ کلید خصوصی برای این انتشار لازم نیست. انتشار موفق باید در Actions و Releases بررسی شود. ساخت و امضای نسخه‌های آینده همچنان به Secretهای اصلی نیاز دارد.
